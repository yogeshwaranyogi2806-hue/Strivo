1. DO WE NEED A BACKEND?
================================================================================

YES - and we already have one. Supabase is our backend.

What Supabase provides:
  - Database: PostgreSQL (already set up with 10 tables)
  - Authentication: Email/password + Phone OTP (already working)
  - Authorization: Row Level Security (already configured)
  - File Storage: Supabase Storage (for content uploads, reports)
  - API: Auto-generated REST + RPC endpoints

We do NOT need to build a separate backend. Supabase handles it all.


================================================================================
2. DO WE NEED A FRONTEND?
================================================================================

YES - and we already have one too. The Flutter mobile app is our frontend.

Since the requirement is MOBILE ONLY, we do NOT need:
  - A separate web frontend
  - The browser prototype (keep as design reference only)
  - A separate admin panel website

4. FLUTTER CODE ORGANIZATION
================================================================================

  main.dart
  app/
    strivo_app.dart              # App entry, router
    router.dart                  # GoRouter with role-based guards
    theme.dart                   # Colors, typography
  core/
    config/                      # App config, Supabase keys
    providers.dart               # Riverpod providers
    models/                      # Data models (Student, Leave, etc.)
    services/                    # Supabase API calls
    utils/                       # Helpers, constants
  features/
    auth/                        # Login, OTP, role detection
    public/                      # Welcome, coaches, content, announcements
    back_office/                 # Admin-only pages
      students/
      attendance/
      leaves/
